# Suppercook — Подводные камни

## Технические

### 1. Галлюцинации AI — главный риск для доверия и безопасности
Модель может «выдумать» рецепт или рекомендовать продукт при аллергии.

**Решение:**
- Гибридный подход: база проверенных рецептов как ядро (RAG), AI адаптирует их под инвентарь.
- Генерация строго через JSON-схему с валидацией (zod).
- **Жёсткая проверка аллергенов на уровне кода, а не промпта.**
- Дисклеймер «Информация не является медицинской рекомендацией».

### 2. Точность распознавания завышает ожидания
Пользователь сфотографировал пакет — приложение не поняло.

**Решение:** UI-паттерн «распознал → подтвердил» (human-in-the-loop); ручной ввод всегда доступен; не блокировать основной сценарий ошибкой.

### 3. Задержки AI убивают UX
Генерация рецепта — 5–15 сек.

**Решение:** стриминг ответа, скелетоны, прогресс «Анализирую ваш холодильник…», кэширование, асинхронные задачи для «тяжёлых» функций (недельный план).

### 4. Себестоимость AI на пользователя
Бесплатный тариф с «безлимитным» ботом — прямой путь к счёту, который съест маржу.

**Решение:** дешёвые модели для простых задач, кэш, дневной лимит генераций → это же монетизация (freemium: 3 рецепта/день бесплатно, далее подписка).

### 5. База продуктов с КБЖУ и конвертация единиц
«2 луковицы», «стакан муки», «пучок зелени» — это не граммы. Без нормализации недельный план с калоражом будет мусором.

**Решение:** готовый источник нутриентов (OpenFoodFacts / USDA / свой справочник) и **хранение инвентаря и рецептов в граммах** с самого начала, перевод «штуки» на этапе ввода по средним значениям. Самая недооценённая работа в проекте.

### 6. Соцчасть = модерация + требования сторов
UGC-контент без модерации = жалобы, бан в App Store (guideline 1.2) и юридические риски.

**Решение:** отложить до v2.0; к этому моменту заложить AI-предмодерацию + жалобы + политику модерации. Чат «один-к-одному» проще, чем публичная лента.

## Продуктовые

### 7. Холодный старт: «а что мне с этим делать?»
Пустой холодильник = пустой продукт.

**Решение:** демо-режим с образцовым набором продуктов, возможность задать типичный набор в один тап, фокус на первом блюде, а не на идеальной инвентаризации.

### 8. Данные инвентаря устаревают
Пользователь не обновляет список → плохие рецепты → отток.

**Решение:** не требовать идеального учёта. Спрашивать «Что изменилось?» при каждом входе, делать инвентарь опциональным (сценарий «просто спросить бота»), мягкие напоминания позже.

### 9. Удержание: готовить — ежедневно, а открывать приложение — нет
**Решение:** привычка строится на планировании (v1.1: «Что готовим завтра?»), а не на заходе «посмотреть что нового». Календарь и weekly-план — именно retention-инструменты, поэтому идут следующими версиями.

### 10. Конкуренция и позиционирование
Whisk, Foodvisor, Cookpad, ИИ-чаты уже существуют; русскоязычный сегмент пока слабее.

**Решение:** дифференцироваться на **«фото из холодильника → готово блюдо» + умный шопинг-лист** для RU-аудитории (локальные продукты, «граммы/штуки/столовые ложки»). Сообщество — долгосрочный удержатель, а не первый хук.
