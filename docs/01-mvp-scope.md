# Suppercook — Структура MVP

> Гипотеза, которую проверяет MVP: **«пользователь с реальными продуктами получает рецепт и готовит его»**.
> Всё остальное — надстройки над этим ядром.

## Логика приоритизации

Каждая функция оценивается по двум осям: **ценность для ядра гипотезы** и **стоимость/риск реализации**.

| Функция | Приоритет | Версия | Обоснование |
|---|---|---|---|
| AI-чат-бот с рецептами «из того, что есть» | P0 | **MVP** | Сердце продукта, самая дешёвая в реализации (API), сразу даёт ценность |
| Распознавание ингредиентов по фото | P0 | **MVP** | Ключевой дифференциатор от «ещё один кулинарный справочник» |
| Умный список покупок (diff «есть / не хватает») | P0 | **MVP** (упрощённый) | Замыкает цикл «готовка → покупка», логически простой, высокая заметность ценности |
| Регистрация, профиль, аллергии/предпочтения | P0 | **MVP** | Без аллергенов AI-рекомендации опасны, без профиля нет персонализации |
| Календарь и планирование меню | P1 | **v1.1** | Ценность есть, но не нужна для первого блюда |
| Недельное планирование + КБЖУ | P1–P2 | **v1.2** | Требует качественной базы нутриентов и конвертации единиц |
| Социальная платформа (чаты, обмен рецептами) | P2 | **v2.0** | Самая дорогая и рискованная: без критической массы аудитории сообщество мёртво, плюс модерация UGC |

## MVP (v1.0) — что входит

1. **Онбординг**: вход (Apple/Google/email), аллергии, предпочтения, цель.
2. **Инвентарь продуктов**: ручной ввод + фото → AI-распознавание → **обязательный шаг подтверждения**.
3. **AI-генерация рецептов**: строго из инвентаря, с указанием, чего не хватает.
4. **Режим готовки**: пошаговые инструкции (крупный текст, таймер).
5. **Умный список покупок**: «в рецепте 8 ингредиентов, у вас есть 5 — добавляем 3».
6. **Сохранение истории** приготовленного.

## Что осознанно НЕ делаем в MVP

- Сообщество и чаты (холодный старт + модерация + юридические риски в сторах).
- Планирование недели и КБЖУ-диеты.
- Push-уведомления «продукты портятся» и прочий retention-набор.
- Собственная ML-модель распознавания (используем готовые API).

**Оценка срока:** 10–14 недель при команде 1 продакт/дизайнер + 2 мобильных + 1 бэкенд.

## Метрики для проверки гипотезы

- **North Star: % пользователей, приготовивших первое блюдо за 7 дней** (цель > 25%).
- Воронка: установка → инвентарь собран → рецепт сгенерирован → готовка начата → блюдо приготовлено.
- D1/D7/D30 retention.
- Количество AI-запросов на пользователя (влияет на себестоимость).

## Дорожная карта

| Версия | Срок | Содержание | Цель проверки |
|---|---|---|---|
| **v1.0 MVP** | 10–14 недель | Инвентарь + фото, AI-рецепты, режим готовки, умный список покупок | Готовят ли из наших рецептов |
| **v1.1** | +6–8 недель | Календарь меню, история, избранное, базовые пуш-уведомления | Привычка и повторное использование |
| **v1.2** | +8–10 недель | Недельный план + КБЖУ + авто-шопинг-лист на неделю | Готовность платить |
| **v2.0** | +12 недель | Сообщество: лента рецептов, чаты, рейтинги + полная модерация | Виральность и долгосрочное удержание |
