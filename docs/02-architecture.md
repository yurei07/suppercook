# Suppercook — Архитектура и стек

## Ключевые принципы

- **Монолит на старте, а не микросервисы.** Микросервисы добавляют операционной боли, которой ещё нет.
- **Все «интеллектуальные» функции — через единый AI-слой**, чтобы менять провайдера и модель без переделки приложения.
- **Тяжёлые AI-вызовы — асинхронные** (фотообработка 3–10 сек) — не блокировать UI.
- **Инвентарь и рецепты хранятся в граммах** — перевод «штуки/стаканы» происходит на этапе ввода.

## Стек

| Слой | Технологии | Почему |
|---|---|---|
| **Mobile (iOS + Android)** | **React Native + Expo (TypeScript)**, EAS для сборок | Один кодbase, быстрые итерации. Альтернатива — Flutter |
| **Backend** | **NestJS (TypeScript)** | Структура, DI, валидация из коробки; весь стек — один язык |
| **База данных** | **PostgreSQL** + **Prisma** | Надёжно держит инвентарь, соцсети, списки. Для разработки — SQLite |
| **Кэш / очереди** | **Redis** + BullMQ | Обработка фото, генерация планов, rate-limit AI |
| **Файлы** | S3-совместимое хранилище (Cloudflare R2 / AWS S3) | Фото продуктов, медиа в сообществе |
| **AI: чат и рецепты** | OpenAI GPT / Anthropic Claude через **единый адаптер** | Structured Output (JSON-схема) → валидный объект рецепта |
| **AI: распознавание фото** | Тот же мультимодальный API (vision) | Один провайдер = одна интеграция |
| **AI-безопасность** | Гибрид: подбор из базы рецептов (RAG) + адаптация LLM | Снижает галлюцинации и риски с аллергенами |
| **Инфра** | Fly.io / Railway / AWS ECS, CI через GitHub Actions | Старт недорого, легко масштабировать |
| **Наблюдаемость** | Sentry (ошибки), PostHog (аналитика), Langfuse (трейсинг промптов) | Без трейсинга не поймёте, почему AI ответил плохо |

## Схема (упрощённая)

```
[Expo RN app: iOS/Android]
        │
   [API: NestJS]  ── auth, inventory, recipes, shopping, planning
        │
  ┌─────┼──────────┬──────────┐
Postgres  Redis    S3       [AI Adapter]
  │                  │         ├─ LLM (рецепты/чат)
  │                  │         └─ Vision (фото)
  └── BullMQ (очереди: фото, планы, уведомления)
```

## AI-слой

```
src/ai/
├── ai.module.ts          — модуль NestJS
├── ai.service.ts         — оркестрация: выбор провайдера, кэш, ретраи
├── providers/
│   ├── ai-provider.interface.ts
│   ├── openai.provider.ts
│   ├── anthropic.provider.ts
│   └── mock.provider.ts   — работает без ключа (для разработки и тестов)
├── schemas/
│   ├── recipe.schema.ts   — JSON-схема рецепта (structured output)
│   └── recognition.schema.ts — схема распознавания ингредиентов
└── prompts/
    ├── recipe-generation.md
    ├── ingredient-recognition.md
    └── allergen-rules.md   — правила фильтрации аллергенов (проверяются кодом, не промптом!)
```

### Важно про безопасность

1. **Аллергены проверяются на уровне кода** после генерации, а не промптом.
2. Рецепты генерируются через **JSON-схему с валидацией** (zod) — некорректный ответ не проходит.
3. Дисклеймер: «Информация не является медицинской рекомендацией».

## Себестоимость AI

- Дешёвые модели для простых задач (классификация, суммаризация).
- Кэширование повторяющихся запросов («паста + яйцо + сыр» генерируем один раз).
- Дневной лимит генераций в бесплатном тарифе → это же монетизация (freemium).
